## szukaj_cpu 1.9.0 – recording and go2rtc (step 1 of replacing Shinobi)

### go2rtc: one connection per camera stream
* go2rtc is bundled (`/opt/szukaj_cpu/go2rtc`) and started by szukaj_cpu with a config
  generated from `szukaj_cpu.toml` (`~/.szukaj_cpu/go2rtc.yaml`, mode 600). It connects to each
  camera stream once; detection, clip buffer and recording read the local restream
  `rtsp://127.0.0.1:8554/<camera>` and `/<camera>_sub`. Restarted automatically if it exits;
  without go2rtc the cameras are read directly as before.
* New `[go2rtc]` section: `enabled`, `binary`, `rtsp_listen` (127.0.0.1 or LAN), `rtsp_port`,
  `api_port`.

### Continuous recording
* New `[recording]` section: `enabled`, `segment_minutes` (default 15, aligned to the clock),
  `retention_days`, `min_free_gb`, `audio`. Per camera: `record`, `record_dir`.
* Files go where Shinobi kept them, with the same names:
  `<recordings>/<group_key>/<shinobi_monitor>/2026-11-19T17-30-00.mp4`.
* Same process as the clip buffer (one connection, two outputs), stream copy. Files being
  written are fragmented MP4 (survive a crash or power cut), finalized to normal MP4 with the
  index at the start (stream copy, low CPU/IO priority). Leftovers are finalized on start.
* Retention by age and by free disk space (oldest first, across cameras).
* Clear log message when the service user cannot write to the recordings directory.

### Web panel
* New sections **Nagrywanie** and **Strumienie (go2rtc)**; per-camera recording switch and the
  resulting directory in the Cameras section.

### Upgrade / trying it out
```bash
sudo apt install ./szukaj-cpu_1.9.0_amd64.deb
sudo chown -R $USER: /path/to/shinobi/videos/GROUP_KEY     # if Shinobi owned it
# panel → Configuration → Nagrywanie → enable; stop Shinobi; Save and restart
```
