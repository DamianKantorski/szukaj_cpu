## szukaj_cpu 1.3.0

### YOLO26
* YOLO26s (Ultralytics, January 2026) is bundled next to YOLO11s, FP32 and INT8. It is
  exported as an end-to-end (NMS-free) model; the detector reads its final boxes directly
  and still supports YOLO11 (raw output + NMS). The format is detected from the model.
* Web panel → Configuration → **Model**: new selector YOLO11s / YOLO26s next to the
  FP32 / INT8 switch. Save and restart to apply.
* Build report on coco128 (128 images, 332 labelled objects, confidence 0.5, FP32 math as on
  CPUs without bf16):

  | model | recall | precision | speed vs YOLO11s FP32 |
  |---|---|---|---|
  | YOLO11s FP32 | 53.9 % | 95.2 % | 1.0× |
  | YOLO11s INT8 | 53.3 % | 94.7 % | ~2.4× (build machine) |
  | YOLO26s FP32 | 53.3 % | 95.7 % | ~1.03× |
  | YOLO26s INT8 | 53.0 % | 95.7 % | ~2.3× (build machine) |

  The models are practically equal on this set; the build machine has VNNI, so measure
  the real speed on the server with `tools/compare_models.py`.

### Tools
* `tools/compare_models.py` reports recall/precision against YOLO-format labels when they
  are present next to the images (e.g. coco128).
* `tools/export_models.py` uses Ultralytics' new `quantize` export option when available.
* `build-deb.sh`: `MODELS="yolo11s.pt yolo26s.pt"` (default), report
  `/usr/share/doc/szukaj-cpu/RAPORT-MODELE.txt`.

### Upgrade
```bash
sudo apt install ./szukaj-cpu_1.3.0_amd64.deb
sudo systemctl restart szukaj_cpu@$USER
```
Your config keeps YOLO11s; to try YOLO26: panel → Configuration → Model.
